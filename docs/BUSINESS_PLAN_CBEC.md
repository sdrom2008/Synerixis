# Synerixis 商业计划（CBEC 修订版）

> 本文替代早期「NexusAI / 国内中小企业全能助手」叙事。旧 `业务计划书.docx` 保留存档，**以本 MD 为准**。  
> 语气：工程可执行，不做融资故事板。  
> **战略定位（2026-09-14）**：对外主叙事为 **「跨境多店客服工作台 + AI 辅助起草」**（人审后发送），**不是**「全自动聊天机器人替人值班」。详见 [`MARKET_FIT_AND_POSITIONING.md`](./MARKET_FIT_AND_POSITIONING.md)。

## 1. 问题与客户

跨境店铺客服面临：

- 多站点（ID/TH/VN/TW…）时区与话术差异，人工跟不过来
- 买家高频问题是「订单到哪了 / 能不能改地址 / 退货怎么走」——可结构化
- 平台规则紧，乱回易被罚；需要可审计的回复链路与人工兜底

**目标客户**：已有 Shopee 和/或 TikTok Shop 在售的中小卖家、代运营工作室（按「店」计费，不是按「企业总部账号」幻想式 SaaS）。

**非目标（Phase1）**：淘宝/抖音国内店、纯品牌官网独立站、无店铺的「AI 创业公司」。

## 2. 产品边界（Phase1）

| 做 | 不做（本阶段） |
|----|----------------|
| 店铺 OAuth 绑定、Webhook 收消息 | 全自动营销投放 / 选品 |
| 意图识别 → 查单/物流摘要 → **AI 草稿 + 人审发送**（允许的官方 autoreply 另议） | 复杂售后仲裁、海关纠纷全自动；Chat API 伪装 chatbot |
| 商户侧转人工、会话列表 | 完整呼叫中心 / 多租户计费引擎打磨 |
| Shopee 优先打透，TikTok 跟进 | Lazada/Amazon 等平台并行铺开 |

成功标准不是「模型多聪明」，而是：**一条真实买家消息能在可接受延迟内得到正确订单状态回复，且可转人工**。

## 3. 一年目标（务实）

| 指标 | Y1 区间 | 说明 |
|------|---------|------|
| 付费店铺数 | **30–100** | 优先深度服务，不做「注册用户过万」KPI |
| 付费转化 | 试用店 → 月付/季付 | 以能跑通闭环的店为准 |
| 平台占比 | Shopee ≥ 70% | TikTok 作第二曲线 |
| 毛利 | 软件订阅为主 | 代运营人天另算，不混进 ARR 吹嘘 |

若 Y1 末仍 <30 付费店：优先查闭环缺口与获客渠道，而不是加功能。

## 4. 收入与单位经济（草案）

详见 [`PRICING_DRAFT.md`](./PRICING_DRAFT.md)。摘要：

- **按店订阅**（Starter / Pro），消息量或会话量封顶
- 超额按量；代运营可加「人工坐席席位」
- 不做「终身买断」；Token/LLM 成本计入 COGS，定价需覆盖

## 5. 获客与交付

1. **服务商 / 代运营**：一次接入多家店，闭环文档（`SHOPEE_CLOSED_LOOP.md`）当验收清单  
2. **卖家社群 / 跨境论坛**：用「查单准确率 + 转人工」案例，不讲空泛 AGI  
3. **交付**：Win11 + VS2022 可本地起 API；生产用自有 VPS/云 + MySQL；密钥客户自持

## 6. 风险（工程视角）

| 风险 | 缓解 |
|------|------|
| 平台 API / Webhook 变更 | `IPlatformClient` 隔离；签名与字段解析单测 |
| Token 过期导致静默失败 | 刷新链路 + 缺配置只打日志不抛（客服侧有兜底话术） |
| OrderAgent 只查库、库空答错 | 下一刀：DB miss → `GetCustomerOrderAsync` 平台回源（见闭环文档） |
| 合规 / 数据驻留 | 最小化存买家 PII；密钥不进 Git |

## 7. 里程碑（工程）

1. Shopee：OAuth → Webhook → Intent → Order → Reply → Handoff 全绿（见缺口清单）  
2. 30 家试用店跑通真实流量  
3. TikTok 对齐同一验收清单  
4. 定价落地计费（可先手工开票，再系统化）
