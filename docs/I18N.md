# CBEC 多语（最小可售）

买家用 **ID / TH / VN / EN / ZH** 进线；坐席用工作语（默认 **ZH**）理解；草稿按买家语重写。  
**不做**全站 UI i18n 包；**不做**无 Key 假流利翻译。

详见演示清单 [`DEMO.md`](./DEMO.md) · Provider [`LLM_PROVIDERS.md`](./LLM_PROVIDERS.md)。

---

## 能力边界

| 场景 | 有 LLM（Admin Provider / 本店 Key / 本地 Ollama） | 无 Key |
|------|--------------------------------------------------|--------|
| 入站语种 | 启发式检测，写入 `ChatMessage.Metadata.lang` | 同左 |
| 一键翻译 | LLM → 工作语，时间线展示原文 + 译文 | **降级**：原文保留 + 明确「无法流利翻译」提示 |
| 草稿重写 | LLM 按 `targetLang` 重写并落库 | **降级**：草稿不动 + 能力边界 Warning |
| 入站自动起草 | `GeneralChatAgent` 按买家语回复 | 规则草稿（中文模板，带「未配置 AI」前缀） |

---

## 配置

| 项 | 位置 | 说明 |
|----|------|------|
| 坐席工作语 `workingLanguage` | merchant-web **AI 设置** → `SellerConfig.PreferredLanguage`（默认 `zh`） | 一键翻译目标语 |
| 支持语种 `supportedLanguages` | 同上 CSV，默认 `ID,TH,VN,EN,ZH` | 草稿语种切换器选项 |
| LLM | Admin「LLM Provider」或 AI 设置 Key | 见 [`LLM_PROVIDERS.md`](./LLM_PROVIDERS.md) |

Schema：`Migrations/AddSupportedLanguages_20260918.sql`（SchemaPatcher 自动补列）。

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/merchant/sessions/{id}/messages` | `items[].lang/translation…` + `i18n.{workingLanguage,supportedLanguages,buyerLanguage,llmConfigured}` |
| POST | `/api/merchant/sessions/{sessionId}/messages/{messageId}/translate` | body 可选 `{ targetLang }`；默认工作语 |
| POST | `/api/merchant/sessions/{id}/draft/rewrite` | body `{ targetLang, content? }`；LLM 成功才更新草稿 |
| GET/PUT | `/api/seller/profile` · `/api/seller/config` | `WorkingLanguage` / `SupportedLanguages` |

## 如何验证（本地）

```bash
# 1) API + seed
cd Synerixis.Api && ASPNETCORE_ENVIRONMENT=Development dotnet run
curl -sS -X POST http://127.0.0.1:7092/api/dev/seed-demo | head

# 2) 商家登录拿 JWT
TOKEN=$(curl -sS -X POST http://127.0.0.1:7092/api/auth/phone-login \
  -H 'Content-Type: application/json' \
  -d '{"phone":"13800138000","code":"123456"}' | python3 -c "import sys,json; print(json.load(sys.stdin).get('token') or json.load(open('/dev/stdin')))" 2>/dev/null)
# 若上面解析失败，用 jq: ... | jq -r .token

# 3) 找印尼语会话
curl -sS -H "Authorization: Bearer $TOKEN" \
  'http://127.0.0.1:7092/api/merchant/sessions' | head

# 4) 打开「演示买家·印尼语」→ 点「译为工作语」
#    无 Key：返回 mode=degrade + warning，原文不变
#    有 Key：时间线出现译文

# 5) 草稿区切换语种 →「按目标语重写」→ 人审发送（SIM mock）
```

UI：`http://localhost:5174` → 收件箱筛选待发草稿 → **演示买家·印尼语**。

## 验收点

1. seed 后存在 **演示买家·印尼语** 会话，买家消息为印尼文，草稿为 ID 文案。  
2. 坐席工作语默认 ZH；AI 设置可改工作语与支持列表。  
3. 无 Key：点「译为工作语」→ 不 500、不编造流利译文，有明确 Warning。  
4. 有 Key：译文写入 Metadata，时间线同时显示原文 + 译文。  
5. 草稿可切换 ID/TH/VN/EN/ZH 后「按目标语重写」；无 Key 时草稿内容不变。  
6. Agent / Seller / Supervisor 均可在收件箱使用（本店会话范围）。  
7. 不做全站 UI i18n；TikTok 扩语种不在本范围。

## 建议真实场景剧本（多角色 + 多语）

| 步 | 角色 | 动作 | 期望 |
|----|------|------|------|
| 1 | Seller `13800138000` | seed → 收件箱打开「演示买家·印尼语」 | 见 ID 原文 + 待审 ID 草稿 |
| 2 | Seller | 无 Key 点「译为工作语」 | degrade 提示；原文仍在 |
| 3 | Admin | 配置 LLM Provider 并 Activate | `GET /api/admin/llm-provider` configured |
| 4 | Agent `agent@demo…` | 登录 →「我的」或全店 → 同会话再译 | 出现中文译文 |
| 5 | Agent | 目标语改 TH →「按目标语重写」 | 草稿变泰语（有 Key） |
| 6 | Supervisor | 人审发送 | SIM mock 出站；时间线坐席气泡 |
| 7 | Seller | AI 设置工作语改 EN，支持列表去掉 TH | 翻译默认英；切换器无 TH |
| 8 | 注入 | 「注入测试」发越南语一句 | 检测 VN；草稿尽量 VN（有 Key）或规则中文（无 Key） |

审计对照：会话名、Metadata.lang、Audit（若有）与草稿 Status=Sent。
