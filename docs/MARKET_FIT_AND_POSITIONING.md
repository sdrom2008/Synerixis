# Synerixis 市场适配与战略再定位

> 读者：工程 / 产品。语气：可执行，不做融资叙事。  
> 日期：2026-09-14。  
> **不编造市场规模数字**；Shopee 政策以 Open Platform FAQ / Chat API 公开说明为准（定性引用）。

## 0. 结论（先读）

| 项 | 决策 |
|----|------|
| **主定位（对外唯一主叙事）** | **跨境多店客服工作台 + AI 辅助起草**（human-in-the-loop copilot + 统一收件箱） |
| **禁止作为公开主 Claim** | 「全自动聊天机器人替人值班 / 7×24 无人值守机器人」 |
| **次要楔子** | 工作台内 **订单 / 物流 / 退款协助**；自动发送仅限政策允许通道（官方 Autoreply API、站外渠道等） |

| **明确砍掉 / 延后** | 竞品分析 Agent、营销文案生成、国内微信登录作核心、假 AGI 叙事 |

## 1. 特征 × 需求矩阵

评分：`匹配` / `部分` / `错位` / `砍掉`

| CBEC 真实需求（2025–26） | 现状能力 | 评级 | 说明 |
|--------------------------|----------|------|------|
| 多店统一收件箱 | 会话列表 / merchant sessions API；多店 UI 仍弱 | **部分** | 有会话闭环骨架，缺「一屏多店」与坐席分配 |
| 7×24 响应率（Shop Rating） | 可自动回，但 Chat API **禁止 chatbot 式主动回复**作合规主路径 | **错位→改** | 响应率目标改由「坐席 + 草稿秒回 + 允许的官方 autoreply」达成，而非伪装全自动 bot |
| 多语言（ID/TH/VN/EN/ZH…） | 无多语 UX / 话术包 | **错位** | 必须进下一刀必做 |
| 订单 / 物流 / 退款协助 | OrderAgent + 平台订单 API 路径已有 | **匹配** | 主产品价值锚点，保留并加深 |
| 人工转接（handoff） | 有转人工标记与会话状态 | **部分** | 需坐席工作台、认领、SLA 计时 |
| ROI / 用量可观测 | dashboard / usage 已接诚实聚合 | **部分** | 缺「人工 vs 草稿采纳」对比与成本面板 |
| AI 草稿（人审后发） | `OutboundMode=DraftFirst` 默认；`DraftMessage` + 商户审核 API | **匹配** | 默认草稿 → 坐席确认 → send；`AutoSend` 仅显式开启并带合规风险文案 |
| Chat API Partner / ISV 准入产品化 | 代码有 OAuth/Webhook；申请与门槛未产品化 | **部分** | 申请材料、店铺订单量门槛、Customer Service 应用类型需进 Onboarding |
| 国内微信登录 / 国内店 | 残留 auth | **砍掉** | 国内平台已封杀路径；不作核心 |
| 竞品分析 / 文案 / 营销 Agent | 能力稀释 | **砍掉** | 偏离客服工作台主线 |
| 「全自动替人值班」营销话术 | 易与 Shopee Chat 禁令冲突 | **错位** | 对外叙事永久降级 |

**竞品参照（定性，不做份额臆测）**：SaleSmartly、晓多、QuickCEP、SmartReply 强在多店收件箱 + 人机协同；Zendesk / Gorgias 在东南亚 CBEC 原生深度偏弱。我们的差异化应落在 **Shopee 闭环工程 + 订单上下文起草**，而非再造通用 bot。

## 2. 平台风险课：国内 → CBEC

### 2.1 已经发生的事

- 用户曾以 **国内淘宝 / 抖音客服** 为方向；平台侧拦截后路径不可持续。
- 教训：**产品叙事与集成方式必须贴合目标平台公开政策**，不能先做「万能自动回」再祈祷审核通过。

### 2.2 Shopee Chat / Open Platform（定性要点）

依据 Shopee Open Platform FAQ / Chat API 公开说明（工程师自行核对最新原文）：

1. **Chat API 禁止**：主动订单更新推送、促销群发、以及 **chatbot 式回复** 等滥用；须使用对应正确 API，不得把 Chat 当广播或无人值守 bot 通道。
2. **准入**：Chat API 对 ISV 有门槛（例如授权店铺近 30 日平均订单量、卖家订单量等条件——以官网当时条款为准）；异常使用可导致 **权限回收**。
3. **`send_message` 校验**：存在内容 / 行为校验限制（公开信息称约 **2025-07** 起加强执行）；违规发送会失败或触发风控。
4. **含义**：把「Webhook → 模型 → 自动 SendReply」当成对外主卖点，**产品与合规双重风险**；代码闭环应保留为「可发送能力」，默认产品行为改为 **辅助起草 + 人审发送**。

### 2.3 对架构的直接含义

| 旧默认 | 新默认 |
|--------|--------|
| EnableAutoReply = 真·自动出站 | `EnableAutoReply`=是否生成草稿；`OutboundMode=DraftFirst\|AutoSend`（默认草稿优先） |
| 营销文案强调「机器人值班」 | 营销强调「统一工作台、秒出草稿、坐席一键发送、Shop Rating 响应」 |
| 国内 WeChat 登录残留 | 从核心路径移除；CBEC 账号体系自洽 |

## 3. 推荐商业定位（选定）

### 3.1 Primary（唯一主叙事）

**「跨境多店客服工作台 + AI 辅助起草」**

- **Unified inbox**：一店或多店买家消息汇入同一工作台。  
- **Copilot draft**：结合订单 / 物流 / 退款上下文生成回复草稿；**坐席编辑确认后发送**。  
- **Human-in-the-loop**：复杂售后、情绪、纠纷默认人工；系统负责提速与降错，不宣称替代坐席。  
- **合规姿态**：不把 Chat API 当 chatbot 广播器；不伪装机器人为真人；自动发送仅走政策允许路径。

### 3.2 Secondary wedge

- 工作台内 **订单 / 物流 / 退款协助**（结构化查询 + 话术建议）。  
- 自动发送：**仅**在政策允许处开启（例如平台官方 Autoreply / 站外渠道）；Shopee Chat 出站默认需人确认（除非后续拿到明确允许的产品能力并写进设置说明）。

### 3.3 一句话（对外）

> Synerixis：给 Shopee / CBEC 卖家的多店客服工作台——AI 根据订单上下文起草回复，坐席确认发送，响应更快、更合规。

### 3.4 明确不说什么

- ❌「全自动聊天机器人 7×24 替人值班」  
- ❌「无人值守跨境客服 AGI」  
- ❌「国内淘宝抖音全能客服」（历史方向，已废弃）

## 4. 使用模型（谁每天点什么）

### 4.1 卖家老板（Seller Owner）

| 日常动作 | 目的 |
|----------|------|
| 绑定 / 授权店铺（OAuth） | 接入消息与订单 |
| 看 Dashboard KPI | 待回复、响应、用量、费用 |
| 开关：草稿模式 / 允许的自动回复策略 | 合规与成本控制 |
| 管理坐席账号与店铺可见范围 | 权限 |
| 看计费与套餐 | 续费决策 |

### 4.2 客服坐席（CS Agent）

| 日常动作 | 目的 |
|----------|------|
| 打开统一收件箱，认领会话 | 处理积压 |
| 查看侧栏订单 / 物流 / 退款摘要 | 少切系统 |
| 一键采用 / 编辑 AI 草稿后发送 | 提速且人审 |
| 标记转人工上级 / 结束会话 | 流程 |
| 切换话术语言（多语） | 站点买家 |

### 4.3 代运营管理员（Agency Admin）

| 日常动作 | 目的 |
|----------|------|
| 批量绑店、按客户分组 | 多店运营 |
| 坐席排班与店铺分配 | 人力 |
| 跨店监控失败发送 / Token 过期 | 稳定性 |
| 导出用量给客户对账 | ROI / 续约 |

## 5. 下一刀必做（排序）

| 优先级 | 能力 | 理由 |
|--------|------|------|
| **P0** | **Draft-first 出站**：默认生成草稿，坐席确认后 `send_message`；自动 send 需显式策略且审计 | 对齐 Chat 政策与主定位 |
| **P0** | **ISV / Customer Service 应用类型申请包**：门槛说明、授权店订单量自检、FAQ 合规声明进产品文档与 Onboarding | 没有 Partner 权限则无产品 |
| **P0** | 多店统一收件箱 MVP（店筛选、未读、认领） | 对标竞品工作台 |
| **P1** | 订单 / 物流 / 退款侧栏与草稿上下文注入加深 | 差异化锚点 |
| **P1** | 多语言 UX + 站点话术包（至少 ZH/EN + 一个 SEA 语种） | CBEC 硬需求 |
| **P1** | Handoff 状态机完善（认领、SLA、超时提醒） | Shop Rating / 响应率 |
| **P2** | 草稿采纳率 / 人工编辑距离等 ROI 指标 | 续费话术有据 |
| **P2** | TikTok Shop 对齐同一工作台模型 | 第二平台 |
| **P2** | 官方允许的 Autoreply / 站外渠道自动发送（与 Chat 严格隔离） | 次要楔子落地 |

## 6. Kill / Defer 清单

| 项 | 处置 | 原因 |
|----|------|------|
| 竞品分析 Agent | **Kill（主线）** | 稀释客服工作台；非付费痛点第一名 |
| 营销文案 / 促销内容生成 | **Kill（主线）** | 与 Chat 禁促销广播叙事易混淆；非 Phase1 |
| 国内微信登录作核心认证 | **Kill / 剥离** | 国内路径已失败；CBEC 账号自洽 |
| 「假 AGI / 万能机器人」营销与产品开关默认 | **Kill** | 政策与信任双杀 |
| 淘宝 / 抖店国内适配 | **Defer 永久（除非政策根本变化）** | 已 pivot |
| Lazada / Amazon 等并行 | **Defer** | 先打透 Shopee 工作台 |
| 完整呼叫中心 / 电话全渠道 | **Defer** | 超出 Y1 范围 |

## 7. Go-to-market & 合规清单

### 7.1 Partner / ISV

- [ ] 按 Shopee Open Platform 申请 **Customer Service**（或当前文档对应的客服类）应用类型，勿用错类目「假装」营销工具。  
- [ ] 自检授权店铺是否满足 Chat API ISV 门槛（近 30 日订单量等——以官网当时条款为准）。  
- [ ] 准备：应用说明、回调域名、权限最小化、数据用途说明（客服辅助，非群发）。  
- [ ] 沙箱联调清单对齐 `docs/SHOPEE_CLOSED_LOOP.md`，通过后再推生产流量。

### 7.2 产品与发送行为

- [ ] 对外文案：**工作台 + AI 起草**，禁止「chatbot 替人值班」主标题。  
- [ ] 默认 **人审后发送**；自动发送与 Chat 通道隔离，设置页写清适用 API。  
- [ ] 不把 bot 伪装成真人坐席；必要处披露「AI 辅助」。  
- [ ] 遵守 `send_message` 校验与频率 / 内容限制；失败可观测、可重试、可转人工。  
- [ ] 禁止用 Chat API 做：促销广播、主动订单骚扰式更新、无人工的 chatbot 循环。  
- [ ] 异常流量熔断：防止被判定异常使用导致 **Chat 权限撤销**。

### 7.3 GTM（务实）

- [ ] 切口：代运营 / 多店卖家「收件箱 + 查单起草」演示（15 分钟）。  
- [ ] 对标话术：相对 SaleSmartly / 晓多 / QuickCEP —— 强调 Shopee 订单上下文闭环与工程可审计，不吹市场份额。  
- [ ] Y1 仍按 `BUSINESS_PLAN_CBEC.md`：**30–100 付费店**，先深度后规模。  
- [ ] 定价对齐 `PRICING_DRAFT.md`（按店订阅）；强调坐席席位与草稿用量，而非「无限机器人消息」。

## 6. Draft-first 落地（2026-09-14）

- Webhook：`ProcessInboundAiReplyAsync` 默认将 AI 回复写入 `draft_messages`，**不**调用 `SendReplyAsync`。
- 商户收件箱：待发送草稿角标；会话详情可编辑 / 发送 / 丢弃。
- 设置：`OutboundMode` 切换；自动发送带风险提示。**不宣称**自动回复计入 TikTok 响应率。
- ISV 申请证据清单见 [`ISV_APPLICATION_CHECKLIST.md`](./ISV_APPLICATION_CHECKLIST.md)。
